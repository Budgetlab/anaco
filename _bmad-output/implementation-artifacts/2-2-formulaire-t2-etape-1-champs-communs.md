# Story 2.2: T2 Form Step 1 — Common Fields

Status: done

## Story

As an instructor,
I want to fill in the common fields of a T2 Hors contrat acte at step 1,
so that I can identify the acte and trigger the processing deadlines.

## Acceptance Criteria

### AC1 — Modal values shown read-only at top of form

**Given** the user has selected T2 / Hors contrat in the modal and clicked "Commencer l'instruction"
**When** the new acte form (step 1) is displayed
**Then** the following values from the modal are visible in read-only badges or text (non-editable inputs / hidden fields):
- Titre: T2
- Périmètre (État or Organisme)
- Type de contrôle (Avis or Visa)
- Catégorie T2: Hors contrat

### AC2 — Common input fields displayed

**Given** the T2 step-1 form is open
**When** it renders
**Then** the following fields are present:
- **Initiales de l'instructeur** (`instructeur`, text, required)
- **Nature de l'acte** (`nature`, dropdown, required) — options filtered by périmètre AND user profile (see AC3)
- **Exercice** (`annee`, year dropdown, required, defaults to current year)
- **Date de saisine** (`date_saisine`, flatpickr date, required — hidden if `etat == 'en pré-instruction'`)
- **Service ordonnateur** (`ordonnateur`, text, optional)
- **Objet** (`objet`, text, optional)
- **Précisions sur l'acte** (`precisions_acte`, textarea, optional)
- **Cet acte a été réalisé en période de services votés** (`services_votes`, checkbox, default unchecked)

### AC3 — Nature dropdown filtered by périmètre and user profile

**Given** the T2 form is displayed
**When** the nature dropdown renders
**Then** if périmètre = État AND user.statut = 'DCB': full list → Annexe financière, Enveloppe limitative, Fongibilité asymétrique, ISP, Marché, Mesure transversale, Référentiel
**And** if périmètre = État AND user.statut = 'CBR': restricted list → Fongibilité asymétrique only
**And** if périmètre = Organisme (any profile): Annexe financière, Enveloppe limitative, Fongibilité asymétrique, Marché, Mesure transversale, Référentiel (ISP excluded)

### AC4 — Périmètre-specific fields

**Given** the T2 form is displayed
**When** périmètre = État
**Then** a **Centre financier** (`centre_financier_code`) field is present with autocomplete (same component as HT2 form), optional

**Given** the T2 form is displayed
**When** périmètre = Organisme
**Then** a **Nom de l'organisme** (`nom_organisme`) field is present with autocomplete (same `autocomplete-organisme` controller as `_form_informations_organisme.html.erb`), required

### AC5 — Nature selection shows/hides nature-specific section

**Given** the instructor selects a nature in the dropdown
**When** the value changes
**Then** a section specific to that nature appears below the common fields (stories 2.3–2.8 implement the content of each section)
**And** when the nature changes, the previously shown section hides and the new one shows
**And** the section is initially hidden (no nature selected)

### AC6 — Budget exécutoire and délibération CA deferred to nature-specific sections

**Given** the T2 step-1 form is displayed
**When** the common fields render
**Then** `budget_executoire` and `deliberation_ca` are **not** present in the common form
**And** these fields will be added in the nature-specific sections (stories 2.3–2.8) only for the natures that require them
**And** this ensures the base form is identical for both État and Organisme périmètres

### AC7 — Auto-generated fields

**Given** the form is saved (POST to create)
**When** the record is persisted
**Then** `numero_utilisateur` / `numero_formate` are auto-generated by the existing `set_numero_utilisateur` after_save callback
**And** `date_limite` is auto-calculated by `calculate_date_limite_if_needed` (J+15 from date_saisine when instructeur is set)
**And** navigation redirects to step 2 (edit_acte_path, etape: 2), same as HT2

### AC8 — Form saves only T2-permitted params

**Given** the form is submitted
**When** the controller processes params
**Then** `titre`, `categorie_t2`, `perimetre`, and `type_acte` are passed as hidden fields and included in `acte_params`
**And** no HT2-specific fields (e.g., `montant_ae`, `numero_chorus`, `beneficiaire`) are present in the T2 step-1 form

### AC9 — No regression on existing HT2 flow

**Given** an acte with `titre = 'HT2'`
**When** the existing new/edit forms are accessed
**Then** all existing HT2 behaviour is unchanged
**And** the routing to the T2 form is gated by `@acte.titre == 'T2'` in `new.html.erb`

## Dev Notes

### Architecture decision: single T2 partial, identical base for both périmètres

The T2 form uses ONE partial `_form_informations_t2.html.erb` for both État and Organisme. The base form is identical across périmètres — the only périmètre-conditional is the 3rd field in row 1 (Centre financier for État, Nom de l'organisme for Organisme).

`budget_executoire` and `deliberation_ca` are **not** in the common form. They apply only to certain natures (not Fongibilité asymétrique for instance) and will be added inside the nature-specific section divs in stories 2.3–2.8. This avoids showing irrelevant fields and keeps the base form clean.

### User `statut` field for T2 nature filtering

`current_user.statut` is a string: `'DCB'`, `'CBR'`, or `'admin'`. Used in controller (`User.where(statut: 'CBR')` line 957). The `set_variables_form` private method already has access to `current_user` via the controller context. Use it directly:

```ruby
# In set_variables_form, new T2 branch:
if @acte&.titre == 'T2' || params[:titre] == 'T2'
  perimetre_t2 = @acte&.perimetre || params[:perimetre]
  if perimetre_t2 == 'etat'
    if current_user.statut == 'CBR'
      @liste_natures = ['Fongibilité asymétrique']
    else # DCB or admin
      @liste_natures = ['Annexe financière', 'Enveloppe limitative', 'Fongibilité asymétrique', 'ISP', 'Marché', 'Mesure transversale', 'Référentiel']
    end
  else # organisme
    @liste_natures = ['Annexe financière', 'Enveloppe limitative', 'Fongibilité asymétrique', 'Marché', 'Mesure transversale', 'Référentiel']
  end
  return # skip HT2 branches below
end
```

### T2 nature display format (epic note)

The epic says "valeur stockée entre parenthèses non incluse" — meaning the dropdown label is the human name (e.g. "Annexe financière") and the stored value is also that name (no separate slug stored in `nature`). The `nature` column is a plain string in `actes`. Use `options_for_select` with identical label/value pairs.

### Budget exécutoire — checkbox vs radio

The existing HT2 organisme form uses a **radio** (Oui/Non, default Oui) for `budget_executoire` (lines 162–179 of `_form_informations_organisme.html.erb`). For T2, use a **checkbox** (default unchecked/false), which is simpler and matches the epic spec language ("case à cocher"). Use `f.check_box :budget_executoire, checked_value: true, unchecked_value: false`.
